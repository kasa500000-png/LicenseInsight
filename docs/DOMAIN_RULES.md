# 날짜·통계·계획 계산 규칙

이 문서는 우리 서비스의 계산 계약이다. 외부 API 실데이터가 없어도 테스트할 수 있다.
구현은 src/domain 순수 함수로 분리하고 UI/API/DB에서 서로 다른 계산을 만들지 않는다.

## A. 날짜와 일정
`LocalDate`: YYYY-MM-DD 형식과 실제 달력 날짜를 모두 검증. 2027-02-29는 유효하지 않다.
`Clock`: 테스트에서 주입한 현재 instant. 이를 Asia/Seoul의 LocalDate로 변환한다.
D-day = target LocalDate와 today LocalDate의 날짜 차이. 밀리초/86400000 반올림 방식 금지.
UTC에서 date-only를 Date로 생성한 후 사용자의 local timezone으로 표시하지 않는다.
extent(single/range)와 temporal_precision(date/datetime)은 독립 필드다.

| 입력·상황 | 출력 계약 |
|---|---|
| 날짜만 있는 접수, 오늘<시작일 | 접수 시작까지 D-N |
| 날짜만 있는 시작일/종료일 당일 | 접수 시작일/마감일 · 시각 공식 확인 |
| 기간 내부 | 접수기간 · 시간/휴일/개인 조건 공식 확인 |
| 시작=끝인 하루 일정 | 당일 시각 확인. 임의 하루 전체를 접수가능으로 처리하지 않음 |
| 시험기간 | 시험기간 시작까지 D-N; 개인 시험일 미확정 |
| stale 또는 pending_change | 기준시각/변경 확인 중 안내를 우선, 접수 가능 단정 금지 |
| known cancelled | 취소/변경 근거를 표시하고 정상 일정 CTA에서 제외 |
| unknown/not_announced | 숫자/가상 일정 없음; 공식 미발표는 공식 근거가 있을 때만 |

정확한 시각을 알더라도 휴일·예외·개인 응시 조건 확인 없이 접수 성공을 보장하지 않는다.
진행 중 접수를 다음 행동 우선 후보로 두고, 없으면 앞으로 시작하는 등록/시험/발표를 단계·관심에 맞게 선택한다.
필기와 실기는 별도 목록이며 실기 자격 보유 여부를 자동 판정하지 않는다.

### 날짜 테스트 oracle — 전부 synthetic
- clock=2026-10-20T14:59:00Z → 한국 2026-10-20 23:59, target=2026-10-21 → D-1.
- clock=2026-10-20T15:00:00Z → 한국 2026-10-21 00:00, 같은 target → D-day.
- 2028-02-28에서 2028-03-01까지 2일, 2027-02-28에서 2027-03-01까지 1일.
- 2026-12-31에서 2027-01-01까지 1일. 미국/한국 기기 timezone에서 동일 결과.
- 날짜가 뒤집힌 기간·올바르지 않은 날짜·알 수 없는 stage는 정상 이벤트로 공개하지 않음.

## B. 통계
`group = qualification + acquisition_track + stage + year + 동일 모집단 정의`.
회차별 자료는 source logical key/revision으로 중복 제거한다.
공식 연간 총계가 있으면 회차 합산과 별도로 보여주며 서로 더하지 않는다.
calculated_rate = passed/examinees*100. round별 비율 단순 평균 금지.
기간 비교는 동일한 완료 범위만. 연도/제도/이름 연속성 미확인 시 주의문구 또는 비교 보류.

| 입력 | 기대 |
|---|---|
| 응시100 합격20 / 응시900 합격450 | 전체470/1000=47.0% |
| 응시0 합격0 | 산출 불가(null), 0%가 아님 |
| 응시100 합격0 | 0.0% |
| 분모 또는 분자 누락 | 해당 회차 산출 불가, complete 연간 집계 금지 |
| 합격>응시 또는 음수 | review_required |
| 회차 duplicate | 중복 제거 후 동일 집계 |
| 40.0%→45.0% | +5.0%p |
| 두 회차 중 한 회차 누락 | 수집된 회차 기준, 공식 연간값 아님 |

공식 비율 원문과 원문 소수 정밀도를 보관한다. 계산값과 반올림 차이 허용은 자릿수에 연동한다.
예: 소수 1자리 반올림으로 확인된 값은 0.05%p 수준의 반올림 차이를 고려하되 임의 오차 확장은 금지.
반올림인지 버림인지 모르면 추측해 통과하지 않고 검토한다.
필기×실기 합격률은 개인 최종 합격확률이 아니다. 낮은 합격률로 난이도 서열을 확정하지 않는다.

## C. 계획
입력: 종목/단계, startDate, targetDate, 요일별 minutes, 제외 LocalDate, 학습항목/단계 비율.
내부 계산 단위는 정수 분. 목표일은 공부기간에서 제외한다.
UI는 시간·분 입력을 허용하되 0~1440분/일을 검증하고 입력 오류를 표시한다.
초기 최대 계획 길이는 366일 제안. 제품 설정값으로 관리하고 한도 초과를 설명한다.
요일별 실제 날짜를 펼침 → 제외일 적용 → capacity 합산 → 단계/항목을 정수분으로 배분한다.
반올림 잔여분은 안정적 순서로 배분해 총 minutes를 정확히 보존한다. 음수/초과 배정 금지.
기간형 시험의 기본 목표는 기간 첫날로 제안하되 개인 시험일이 아니라는 점을 표시하고 수정 가능하게 한다.

- 월~일 7일 중 평일5×60 + 주말2×180 = 660분(11시간).
- 그중 평일 하루 제외 → 600분(10시간).
- startDate>=targetDate, 모든 시간0, 모든 날짜 제외 → 생성 불가 이유·수정 항목 안내.
- 동일 입력은 동일 배분. 완료 체크 후 화면 새로고침은 완료상태 유지.
- 목표/요일시간 변경 시 기존 완료 항목을 보존할지 사용자에게 명시적 선택을 제공한다.
- 공식 시험 일정이 바뀌어도 개인 계획을 몰래 수정하지 않고 재계산 제안만 한다.

## D. 공통 API/결과 타입 설계
순수 함수는 `{ok:true,value,warnings}` 또는 `{ok:false,code,fieldErrors}` 형태 등 typed result를 선택한다.
운영자/사용자 입력 오류와 예상치 못한 시스템 예외를 구분한다. 에러 메시지에 원문·키를 넣지 않는다.
표시 반올림은 presentation 단계에서 하고 내부 계산 원본은 보존한다.
