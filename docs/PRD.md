## 1. 목표와 비목표

목표는 수험생이 한 종목의 다음 일정을 확인하고, 필기·실기 통계를 이해하며, 자신의 공부시간에 맞춘 준비 계획을 저장하도록 돕는 것이다. 로그인 없는 모바일 우선 웹으로 출시하고 검색을 통한 유입과 광고형 운영 가능성을 검증한다.

비목표는 공식 시험접수 대체, 개인별 응시자격 확정, 합격확률 예측, 강의 판매, 기출문제 수집, 커뮤니티 운영, 서비스 내 실시간 LLM 호출이다.

## 2. 우선순위 정의

- **P0:** 공개 MVP 출시 전 반드시 충족.
- **P1:** 실제 사용성·수요 확인 후 추가.
- **P2:** 별도 기획과 데이터 검증이 필요한 확장.

P0 = 탐색·상세·일정·통계·2~3개 비교·관심 저장·규칙 기반 계획·ICS 내보내기·출처·최소 운영자 기능·검색 최적화·광고 비활성 기본 구조.
P1 = 계정 동기화·일정 변경 알림·독립적인 비교 가이드 확장.
P2 = 다른 시행기관·국가전문자격·맞춤형 AI 상담·커뮤니티·구인 정보 결합.

## 3. 핵심 사용자 여정

**여정 A — 검색 유입:** 종목 상세 페이지 접속 → 다음 접수·시험 구분 확인 → 최신 통계의 기준 확인 → 관심 저장 또는 공식 접수처 이동.

**여정 B — 선택:** 자격증 탐색 → 2~3개 선택 → 동일 연도·동일 단계 통계와 일정 비교 → 목표 종목 선택.

**여정 C — 실행:** 목표 회차·개인 목표일 선택 → 주간 공부 가능시간·할 일 입력 → 주차별 계획 생성 → 브라우저 저장 → 일정 내보내기.

**여정 D — 장애:** 외부 API 장애 발생 → 마지막 검증 데이터와 갱신 지연 경고 확인 → 공식 출처 이동. 데이터가 전혀 없으면 확인 불가 화면을 제공하고 가상 값을 대신 노출하지 않는다.

## 5. 기능 요구사항·수용 기준

### FR-01. 자격증 탐색 — P0

이름, 운영자가 검증한 별칭, 등급, 직무분야로 탐색한다. 공백·대소문자 등 안전한 정규화만 자동 수행한다. 검색 결과의 공식 종목명과 사용자의 입력 별칭을 혼동하지 않는다.

**수용 기준:** 지원하는 공식 이름·별칭으로 같은 종목을 찾는다. 결과가 없으면 미지원 또는 검색어 확인을 안내한다. 데이터 없는 가짜 상세 페이지를 만들지 않는다. 비교 선택은 3개까지만 가능하다.

### FR-02. 종목 상세 — P0

첫 화면은 종목명, 등급, 다음 확인된 접수·시험 정보, 관심 저장, 공식 페이지 이동으로 구성한다. 필기·실기 접수와 시험·발표를 별도 이벤트로 표시한다. 정보의 기준일·마지막 확인일·출처를 제공한다.

**수용 기준:** 공식 기록과 표시 값이 일치한다. 기간을 단일 시험일로 축약하지 않는다. API 조회 시각을 공식 발표 시각처럼 표시하지 않는다. 공식 접수 링크는 검증된 기관 도메인으로만 연결한다. 사이트가 접수를 대신 완료했다고 표시하지 않는다.

### FR-03. 일정·D-day — P0

공식 날짜는 `Asia/Seoul` 기준으로 해석한다. D-day는 시간 차를 24시간으로 나누는 방식이 아니라 한국 달력 날짜의 차이로 계산한다. 접수·시험·발표의 기준을 D-day 옆에 명시한다.

날짜만 있고 시각이 없으면 09:00·18:00·23:59 등을 임의로 넣지 않는다. 접수 시작일·마감일 당일은 “시각 공식 확인” 상태를 제공한다. 오래된 데이터로 현재 접수 중이라고 단정하지 않는다.

**수용 기준:** 전날·당일·다음날, 월말·연말·윤일, 다른 기기 시간대에서 날짜 테스트를 통과한다. 범위형 시험에 “시험기간 시작까지”와 “개인 시험일 미확정”을 표시한다. 미래 연도의 빈 응답을 곧바로 “미발표 확정”으로 해석하지 않는다.

### FR-04. 합격률 분석 — P0

확인 가능한 최근 최대 5개 완료연도와 회차별 통계를 표시한다. 현재 연도 자료가 일부만 있으면 “진행 중·수집된 회차 기준”으로 분리한다. 필기·실기, 응시자·합격자·합격률을 함께 표시한다.[S03]

연간 합격률 = 동일 종목·단계·취득방식에서 중복 제거된 회차의 합격자 합 ÷ 응시자 합 × 100. 회차별 비율의 단순 평균은 사용하지 않는다. 분모 누락·0명은 0%가 아니라 산출 불가다. 누락 회차가 있으면 공식 연간 수치로 이름 붙이지 않는다.

공식 제공 비율과 자체 계산 비율을 보관·구분한다. 소수 자릿수 차이를 허용하되 설명할 수 없는 불일치는 검토 대기 상태로 둔다. 필기·실기 합격률을 곱해 최종 합격확률을 만들지 않는다.

**수용 기준:** 회차1 응시 100·합격 20, 회차2 응시 900·합격 450이면 연간 값은 47.0%다. 35.0%는 실패다. 차트와 표의 값이 일치한다. 표본 수, 기준 연도, 자료 범위가 명시된다. 낮은 합격률을 곧바로 높은 난이도로 단정하지 않는다.

### FR-05. 자격증 비교 — P0

2~3개 종목의 등급, 확인된 일정, 동일 기준의 필기·실기 통계, 응시 수수료(검증된 경우), 공식 시험정보를 비교한다. 서로 다른 완료연도만 존재하면 각각의 연도를 명시하고 직접 순위 비교를 하지 않는다.

**수용 기준:** 데이터가 없는 칸은 “확인 불가”다. 선택 순서가 달라도 공유 URL의 정규화 결과는 일관된다. 서로 다른 시험기간이 겹치면 “기간 중복 가능성”으로 안내하며 개인 시험시간 충돌을 확정하지 않는다. 비교 값과 상세 값이 일치한다.

### FR-06. 관심 저장 — P0

로그인 없이 해당 브라우저에 최대 10개 관심 종목을 저장한다. 저장 한도는 제품 설정값으로 관리한다. 데이터 삭제·시크릿 모드·기기 변경 시 유지되지 않을 수 있음을 안내한다.

**수용 기준:** 새로고침 후 유지되고 삭제할 수 있다. 저장소 사용 거부·용량 오류에서도 페이지가 동작한다. 서버 렌더링 중 localStorage 접근 오류가 없다. 개인 목록은 검색엔진 HTML과 분석 로그에 포함하지 않는다.

### FR-07. 규칙 기반 준비 계획 — P0

입력: 종목·단계, 시작일, 목표일, 평일·주말 등 요일별 공부시간, 제외일, 사용자가 입력하거나 검토된 템플릿에서 선택한 학습항목.

계산: 시작일부터 목표일 전날까지의 각 날짜별 가능시간을 합산하고 선택한 단계 비율에 따라 학습·문제연습·복습 등을 배분한다. 비율은 편집 가능한 계획 템플릿일 뿐 공식 권장 학습량이 아니다. 필기와 실기에 동일 템플릿을 강제하지 않는다. 합격에 필요한 총시간을 지어내지 않는다.

기간형 시험은 기간 시작일을 보수적 기본 목표로 제안하되 “내 시험일이 아님”을 명시하고 직접 날짜를 바꿀 수 있게 한다.

**수용 기준:** 과거 목표일, 0시간, 제외일로 모두 채워진 기간을 처리한다. 7일 구간에 평일 5일×1시간·주말 2일×3시간이면 총 11시간이다. 반올림 후 작업 배정 총합이 총 가능시간을 넘지 않는다. 생성 근거를 설명하고 사용자가 수정·삭제·완료 체크할 수 있다.

### FR-08. 일정 내보내기 — P0

선택한 공식 일정 또는 사용자 계획을 `.ics`로 내보낸다. 날짜만 있는 이벤트는 종일 일정으로 생성한다. ICS 종료 날짜는 배타적 끝 날짜로 처리하며 며칠짜리 기간은 끝 날짜 다음날을 기록한다. 검증된 표준 라이브러리를 사용한다.

**수용 기준:** 한국어 제목, 안정적인 UID, 날짜·기간·출처가 유지된다. 미확인 시각을 넣지 않는다. “가져온 일정은 자동 갱신되지 않으며 변경 시 다시 확인”을 안내한다. 운영 화면은 캘린더 앱의 가져오기 완료나 알림 발생을 보장하지 않는다. 파서 테스트와 최소 1개 실제 캘린더 가져오기 검증을 기록한다.

### FR-09. 콘텐츠·출처·정정 — P0

공식 사실, 자체 계산, 편집 가이드를 화면에서 구분한다. 출처와 데이터 검증 시각을 표시한다. 편집 글은 초안·검토·게시 상태를 둔다. 정정 요청은 수신 가능한 운영자 연락처를 사용하며 실제 수신 테스트를 한다.

**수용 기준:** 게시된 가이드의 시험 관련 사실에는 근거가 있다. 존재하지 않는 연도별 일정을 게시하지 않는다. 정정 시 전후 값·사유·출처·처리자를 추적한다. 공식 기관의 로고·합격 후기·사용자 수를 임의로 사용하거나 꾸미지 않는다.

### FR-10. 운영자·데이터 관리 — P0

방문자 계정은 만들지 않지만 최소 운영자 로그인은 허용한다. 수집 성공·실패, 미매핑 종목, 통계 불일치, 일정 변경을 확인한다. 운영자는 검토 결과를 기록하고 게시를 중단·재개할 수 있다. 글 편집은 Git 관리 Markdown 중심으로 시작해 대형 CMS를 만들지 않는다.

**수용 기준:** 일반 방문자와 일반 인증 사용자는 관리자 데이터 접근·변경이 불가능하다. 역할은 서버 관리 권한으로 결정하고 사용자 수정 메타데이터를 신뢰하지 않는다. 수동 동기화는 인증·권한·속도 제한·감사로그를 거친다.

### FR-11. 검색 최적화 — P0

핵심 공개 콘텐츠는 서버에서 HTML로 제공한다. 페이지별 title·description·canonical·OG 정보·sitemap을 구성한다. 실제 내용에 맞는 구조화 데이터만 사용하고 검색 노출 기능을 보장하지 않는다. Next.js 메타데이터 기능을 구현 수단으로 사용할 수 있다.[S11]

**수용 기준:** 자바스크립트 실행 전 HTML에 종목명·핵심 설명·검증 데이터가 존재한다. 운영 canonical은 운영 도메인이다. 검색·비교 조합을 사이트맵에 무한 추가하지 않는다. preview·개인 계획·admin은 색인에서 제외한다. 삭제·미존재 종목은 적절한 상태코드를 반환한다.

### FR-12. 광고·분석 — P0 구조 / 실광고 활성화는 출시 후 승인 단계

광고 슬롯과 분석 이벤트를 추상화한다. 기본값은 OFF다. 공개 환경·운영자 설정·광고 계정 검토·동의 조건을 충족한 페이지에서만 실광고를 표시한다. 개인정보·동의 의무는 실제 도입 도구와 대상 이용자 지역에 맞춰 출시 전에 검토한다.[S08][S16]

개발·preview·자동 테스트·관리자·오류·빈 검색결과·개인 계획 화면에서는 실광고를 로드하지 않는다. 가짜 광고 클릭 이벤트를 발생시키지 않는다. 운영자와 자동화 도구의 실광고 클릭은 금지한다.[S14]

**수용 기준:** 광고 스크립트 실패·차단·동의 거부 시에도 기능이 작동한다. 핵심 일정·버튼을 가리거나 오클릭을 유도하지 않는다. placeholder 높이를 잡아 레이아웃 이동을 줄인다. 게시자 ID와 ads.txt는 실제 계정 제공 값만 쓴다. 광고 OFF 비상 스위치가 동작한다.

분석 이벤트: qualification_view, comparison_completed, favorite_saved, plan_created, plan_saved, calendar_exported, official_link_clicked. 익명 집계에 필요한 최소 속성만 수집하고 입력 자유문구·이메일·개인 계획 내용·광고 클릭을 자체 추적하지 않는다.

## 6. 상태 설계

네트워크·외부 데이터 상태와 시험 일정 상태를 분리한다.

| 데이터 상태 | 화면 동작 |
|---|---|
| verified | 확인된 값·출처·확인시각 표시 |
| stale | 마지막 확인 자료 + 갱신 지연 경고; 현재 상태 단정 제한 |
| unknown | 확인 가능한 자료 없음; 0값으로 변환하지 않음 |
| unsupported | 현재 지원 범위가 아님 |
| not_announced | 공식 근거로 미발표가 확인된 경우에만 사용 |
| review_required | 충돌·매핑 불명확; 해당 신규 값 공개 보류 |
| error | 최초 수집 실패 등 제공 불가 안내·공식 출처 이동 |

한 종목의 통계 실패가 정상 일정까지 숨기지 않도록 기능별 상태를 관리한다.

## 7. 기술 아키텍처

기본 제안: Next.js App Router + TypeScript + Supabase Postgres + GitHub + 상업 이용 가능한 호스팅. UI는 재사용 가능한 작은 컴포넌트로 구성하고 단위 테스트·브라우저 E2E를 함께 둔다. 라이브러리·런타임 버전은 착수 시 공식 지원 범위를 확인하고 lockfile로 고정한다.

공공 API → 서버 수집 어댑터 → 원문 보관·검증 → 정규화 DB → 공개 읽기 모델 → 서버 HTML·캐시 → 이용자.

이용자 요청으로 외부 공공 API를 직접 호출하지 않는다. 정적 내용은 캐시하고 날짜에 따른 상태는 갱신 수명과 한국 날짜 경계를 고려한다. 광고·분석은 부가 기능이며 핵심 도메인 계산과 분리한다. 일정·통계·계획 계산 함수는 외부 API와 독립된 순수 함수로 작성한다.

Vercel 사용 시 상업 서비스에 적합한 플랜으로 운영한다. 무료 Hobby를 광고형 운영의 전제로 두지 않는다.[S07]

## 8. 데이터 모델 개요

| 엔터티 | 핵심 역할 |
|---|---|

| pass_statistics | 연도·회차·단계·응시자·합격자·공식 비율·검증 상태 |

가이드 본문은 Git 관리 Markdown을 기본으로 한다. 관심 목록·준비 계획은 localStorage에 저장하고 MVP 서버 DB에 개인 학습기록 테이블을 만들지 않는다. 향후 동기화 도입 시 별도 설계한다.

공개 DB 스키마에는 RLS와 명시적 권한을 적용한다. 익명 사용자는 게시된 읽기 자료만 조회하고 쓰기는 금지한다. 원문·관리 데이터는 공개하지 않는다. 비밀키·service role은 클라이언트에 넣지 않는다.[S12][S13]

## 9. 디자인·접근성 요구사항

제안 토큰: 배경 #F8FAFC, 표면 #FFFFFF, 본문 #0F172A, 보조 #475569, 강조 #2563EB. 상태는 텍스트·아이콘을 함께 사용한다. 대비는 실제 조합으로 검사한다.

본문 16px 이상을 기본으로 하고 버튼 터치 영역은 44px 이상을 목표로 한다. 4·8·12·16·24·32px 간격, 12px 카드 반경, 데스크톱 최대 본문 폭 약 1120px를 기본안으로 한다. 접근성은 키보드 탐색·초점·읽기 순서·명시적 라벨·차트 표 대체를 포함한다.

검증 화면 폭: 360 / 390 / 768 / 1440px. 모바일 비교 표는 항목명이 유지되는 가로 스크롤을 허용하되 페이지 전체 가로 넘침은 금지한다. 로딩·빈 값·오류·오래된 데이터·저장소 오류·광고 차단 상태를 별도로 디자인한다.

## 11. 측정·성공 기준

핵심 행동 전환율 = 상세 페이지를 본 세션 중 관심 저장·계획 저장·ICS 내보내기·공식 접수처 이동 중 하나 이상 수행한 세션 / 상세 방문 세션. 중복 행동은 세션당 한 번 집계한다.

함께 볼 지표: 검색 노출·클릭, 대표 페이지 색인 상태, 비교 완료율, 계획 생성→저장 전환, 갱신 지연 종목 수, 수집 오류율, 운영자의 수동 검토 부담, 실측 광고 매출과 비용. 동의 거부·차단 등으로 측정되지 않는 이용자가 있으므로 관측 데이터의 한계를 표시한다.

목표 수치는 출시 후 기준선을 확인해 확정한다. 초기 사용성 테스트는 5명 중 4명이 도움 없이 일정 확인·계획 저장을 완료하는 것을 내부 목표로 삼는다.

## 12. 출시 게이트

G0 데이터: 사용 승인·실호출·코드 매핑·종목별 범위·기간·통계 의미 확인.
G1 제품: 핵심 여정과 P0 요구사항 충족, 가상 데이터 운영 차단.
G2 신뢰: 샘플 일정 공식 대조, 집계 테스트, 출처·정정·운영자 검증.
G3 운영: 상업 호스팅 조건·비밀키·RLS·로그·백업·복원·비용 알림 확인.
G4 공개: preview 색인 차단, 운영 검색 설정·모바일 QA·실측 성능 검토.
G5 광고: 광고 승인·정책·개인정보·필요 동의 설정·테스트 차단·운영자 활성화 승인.

실광고 승인 없이도 G0~G4를 충족하면 광고 OFF로 공개할 수 있다. API 실호출이 막혔을 때는 데모·단위 테스트·UI를 진행하되 G0와 공개 데이터 검증 완료를 선언하지 않는다.

## v2 명확화

- 날짜의 정밀도(date/datetime)와 단일일/기간(single/range)을 분리한다. 화면에서 알 수 없는 시각을 채우지 않는다.
- 접수기간에 포함되더라도 휴일·기관 예외·개인 조건을 확인하지 않은 상태에서 “지금 접수 가능”을 보장하지 않는다.
- 광고 OFF 구조는 STEP-16에서 구축하고 STEP-18 QA 및 STEP-19 공개 전에 검증한다. 실광고는 STEP-20에서 별도 승인 후 활성화한다.
- 공개 페이지의 데이터 키/조회 시각/검증 시각과 운영자 검토 시각을 분리하며, 자동 스키마 검증을 사람의 공식 대조로 표시하지 않는다.
- P0 JSON은 내보내기다. JSON 가져오기·계정 동기화는 후속 범위이며 임의 추가하지 않는다.
- 기능 구현 완료와 실데이터 공개 가능 여부를 별도 상태로 기록한다. fixture 테스트 성공은 G0 충족이 아니다.
