## 1. 서비스 정의

**공식 자격시험 정보를 수험생의 다음 행동으로 연결하는 모바일 우선 웹사이트.**

자격증 검색 → 다음 접수·시험 일정 확인 → 필기·실기 통계 비교 → 가능한 공부시간으로 준비 계획 구성 → 관심 자격증 저장·공식 접수처 이동까지 한 흐름으로 제공한다.

브랜드 가칭은 `자격인사이트`, 코드명은 `qualification-insight`다. 도메인·상표 사용 가능성은 조사하지 않았으며 확정하지 않는다. 공식 Q-Net 또는 정부 운영 서비스로 오인시키지 않는다.

## 2. 사업 가설과 검증 원칙

일정·통계 조회를 넘어 계산, 비교, 준비 행동을 돕는 기능이 검색 유입 후 재방문을 만든다는 가설이다. 검색량, 경쟁 사이트 트래픽, 광고 RPM, 광고 승인 가능성은 아직 실측하지 않았다. 이 문서는 수익 보장이 아니라 검증 가능한 제품 설계다.

| 가설 | 초기 검증 방법 | 실패 시 조정 |
|---|---|---|
| 일정 확인 수요가 상세 페이지 유입으로 이어진다 | Search Console의 실제 검색어·노출·클릭 확인 | 제목·내용·지원 종목을 검색 의도에 맞춰 수정 |
| 비교·준비 계획이 단순 조회보다 유용하다 | 비교 완료·계획 저장·캘린더 내보내기 행동 측정 | 사용되지 않는 기능 확장을 중단 |
| 신뢰할 수 있는 정제·해설 콘텐츠가 광고형 운영에 적합하다 | 콘텐츠 품질 검토와 실제 광고 심사 | 승인을 전제로 지출하지 않고 품질·독자 가치 개선 |
| 한 사람이 운영할 수 있다 | 오류 처리 횟수·수동 검수 시간을 기록 | 종목 수 축소, 데이터가 좋은 분야에 집중 |

## 3. 타깃 사용자와 해결할 문제

| 사용자 | 상황 | 해결할 문제 |
|---|---|---|
| 직장인 수험생 | 평일 저녁·주말에 공부 | 다음 회차까지 실제로 확보할 수 있는 시간을 계산하기 어렵다 |
| 취업 준비생 | 2~3개 자격증 중 선택 | 일정·필기·실기를 같은 기준으로 비교하기 어렵다 |
| 재응시자 | 필기 또는 실기 재도전 | 단계별 접수·시험·발표를 구분해 챙겨야 한다 |

핵심 문장: **“언제 접수하고, 무엇을 비교하고, 오늘부터 어떻게 준비할지.”**

## 4. 차별화 방향

공식 정보를 대체하는 시험 접수 플랫폼이 아니다. 공식 출처로 이어지는 준비·비교 도구다.

- **행동 중심 일정:** 접수기간, 시험기간, 발표일을 구분하고 다음 행동을 우선 노출한다.
- **정직한 통계:** 필기·실기 분리, 응시자 수 동시 표기, 연간 가중 집계, 불완전 연도 표시를 기본값으로 둔다.
- **규칙 기반 준비 계획:** 이용자가 입력한 목표일·가능시간·학습항목을 배분한다. AI 합격 예측을 하지 않는다.
- **개인화 재방문:** 로그인 없이 관심 자격증과 준비 계획을 해당 브라우저에 저장한다.
- **설명 가능한 콘텐츠:** 데이터 기준, 계산 방법, 마지막 확인 시점과 수정 이력을 보여준다.

## 5. 서비스 범위

### MVP 출시 범위

한국산업인력공단 시행 국가기술자격의 기사·산업기사·기능사 중 검증된 10개 종목을 목표로 한다. 최초 데이터 검증은 전기기사·전기산업기사·전기기능사 3종목으로 진행해 등급별 차이를 확인한다.

10개 후보: 전기기사, 산업안전기사, 정보처리기사, 건설안전기사, 소방설비기사(전기분야), 소방설비기사(기계분야), 전기산업기사, 산업안전산업기사, 전기기능사, 위험물기능사.

이 목록은 검색량 순위가 아니다. 실제 공식 종목명·종목코드·시행 여부·API 자료 범위를 확인한 뒤 확정한다. 사용자의 산업 현장 이해를 콘텐츠 검수에 활용하되, 응시자격을 개인별로 판정하지 않는다.

### 제외 범위

컴퓨터활용능력은 대한상공회의소 시행 종목이므로 현재 HRDK 중심 통합 범위에 자동 포함하지 않는다.[S06] 공인중개사 등 국가전문자격, 과정평가형·일학습병행, 민간자격, 어학시험, 전국 상시시험 좌석 현황은 별도 검증 후 확장한다.

방문자 회원가입, 커뮤니티, 기출문제 무단 수집, 유료 강의, 문제풀이 채점, AI 챗봇, 개인 합격확률, 자동 원서접수, 이메일·문자·푸시 알림은 MVP에 넣지 않는다. 캘린더 파일 내보내기는 알림 서비스나 자동 동기화가 아니다.

## 6. 수익 모델

1차 모델은 공개 정보·분석 페이지의 디스플레이 광고다. 2차로 실제 사용량과 신뢰가 생긴 후 교재·강의 제휴를 검토하되, 광고와 제휴 여부를 명확히 표시한다. 핵심 일정·통계·준비 계획을 광고 시청 조건으로 잠그지 않는다.

광고는 출시 초기 기본 OFF다. 승인·정책·동의 설정과 운영자 확인 후 활성화한다. 상세 페이지의 핵심 일정 아래와 충분한 본문 뒤 등 제한된 구역부터 검증한다. 광고 클릭률을 제품 최적화 목표로 삼지 않는다.

Google은 부가가치 없는 복제 콘텐츠, 낮은 가치의 화면, 오작동을 유도하는 광고 배치를 제한한다.[S08] 검색 순위 조작을 목적으로 가치 낮은 페이지를 대량 생성하는 방식도 배제한다.[S09]

### 손익 계산 예시 — 시장 추정치가 아닌 가정

월 광고 매출 = 월 페이지 조회수(PV) ÷ 1,000 × 실측 페이지 RPM.
월 고정 운영비가 100,000원이고 실측 페이지 RPM이 3,000원이라면, 단순 고정비 회수에 필요한 PV는 약 33,334회다. 세금, 제작 시간, 변동비는 별도다. 3,000원을 국내 평균 단가로 해석하지 않는다.

## 7. 콘텐츠·검색 전략

처음부터 수백·수천 종목 페이지를 생성하지 않는다. 10개 상세 페이지, 유용한 공통 가이드, 실제로 내용 차이가 있는 비교 콘텐츠부터 시작한다. 페이지 개수 자체는 광고 승인 조건이나 순위 보장이 아니다.

상세 페이지는 공식 개요·다음 일정·단계별 통계·해석상의 주의점·준비 계획 진입·출처로 구성한다. 자동 산출 가능한 수치 요약은 정해진 템플릿을 이용한다. GPT가 만든 설명 글은 출처 검증·편집 후 게시한다.

연도·필터·검색어 조합마다 색인 가능한 URL을 무한 생성하지 않는다. 종목 대표 URL을 유지하고, 연도별 별도 문서는 독립적인 자료 가치가 있을 때만 만든다. 미확인 미래 연도를 넣은 일정 페이지와 AI가 지어낸 FAQ는 게시하지 않는다.

## 8. 사용자 경험과 디자인

디자인은 화려한 학원 광고 페이지보다 읽기 쉬운 정보 서비스에 가깝게 구성한다. 밝은 배경, 진한 본문, 한 가지 강조색, 충분한 여백을 사용한다. 큰 그라디언트·과도한 배지·장식용 AI 문구를 피한다.

모바일 하단 내비게이션은 홈·일정·비교·내 준비의 4개로 제안한다. 홈의 검색으로 탐색 페이지에 접근한다. 자격증 상세에서는 다음 일정이 첫 화면에 보이고, 합격률·기본정보·출처는 아래로 이어진다. 광고가 공식 접수 버튼과 시각적으로 붙지 않도록 한다.

차트는 표와 함께 제공한다. 색상만으로 필기·실기를 구분하지 않는다. 디자인 토큰과 접근성·반응형 목표는 PRD에서 정의한다.

## 9. 운영 모델

공공 API는 방문자 조회마다 호출하지 않는다. 예약 수집 → 검증 → DB 저장 → 캐시된 페이지 제공 구조로 운영한다. API의 실시간 갱신 표기는 미래 일정·과거 통계의 완전성이나 무중단을 보장하지 않는다.

자동 검증 오류, 종목명 매핑 충돌, 공식 일정 변경은 운영자 검토 대기열에 올린다. 검증 실패는 기존 정상 데이터를 삭제하는 신호가 아니다. 중요한 일정이 바뀌면 기존 값·새 값·출처·확인일을 기록한다.

개발·미리보기와 운영 환경을 분리한다. 광고·비밀키·가상 데이터가 운영 환경에 섞이지 않도록 배포 게이트를 둔다. 운영자용 최소 화면은 수집상태, 매핑 검토, 게시 여부, 정정 이력에 한정한다.

## 10. 비용 원칙

사용자에게 익숙한 Next.js·Supabase·Vercel 조합을 기본 제안으로 삼되, 유료 서비스 구매는 별도 승인이 필요하다. Vercel Hobby는 비상업적 개인 용도로 제한되므로 광고 수익 목적 배포에 무료 Hobby를 전제하지 않는다.[S07]

공공데이터 API 이용료와 서버·DB·도메인·광고 및 분석 도구 운영비는 구분한다. 운영비 상한, 사용량 알림, 긴급 광고 비활성화와 수집 중단 기능을 출시 전에 설정한다. 사이트 내 GPT API 호출은 MVP에서 0회로 설계한다. 사용자의 GPT·Codex 개발 도구 비용과 서비스 운영 비용은 별도 항목이다.

## 11. 출시 후 검증 목표

아래 값은 내부 검증용 제안이며 전망치가 아니다.

| 시점 | 목표 | 판단 |
|---|---|---|
| 출시 전 | 10개 종목의 지원 범위·출처·일정 검수 완료 | 미달이면 종목을 줄이고 공개 범위를 명시 |
| 초기 사용성 테스트 | 5명 중 4명이 도움 없이 일정 확인과 계획 저장 완료 | 실패한 화면을 개선한 뒤 확장 |
| 공개 후 30일 | 색인·검색 유입과 핵심 행동의 측정 정상 여부 확인 | 데이터가 적으면 성공·실패를 성급히 판단하지 않음 |
| 공개 후 90일 | 28일 단위 유기적 유입 추세, 기능 사용, 수동 운영 부담 검토 | 확장·집중·축소 결정 |

제품 핵심 지표는 자격증 상세 방문 중 관심 저장·계획 저장·일정 내보내기·공식 접수처 이동 중 하나를 실행한 세션 비율이다. 단순 PV 증대를 위해 페이지를 쪼개지 않는다.

## 12. 우선순위 결론

**데이터 연결 검증 → 한 종목 핵심 여정 완성 → 10개 종목 공개 → 검색 성과 확인 → 광고 활성화.**

운영할 수 없는 광범위한 포털보다, 날짜와 계산이 정확하고 이용자가 다시 찾을 이유가 있는 작은 서비스부터 만든다.
