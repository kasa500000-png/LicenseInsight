# 전체 화면 명세

## 공통
모든 공개 데이터 블록은 기준 연도/회차, 출처, 마지막 자동 검증 및 필요시 운영자 대조 시점을 보여준다.
상세의 통계가 없더라도 정상 일정은 표시한다. 상태를 페이지 전체 1개 boolean으로 처리하지 않는다.
모바일은 목록 중심이며 키보드/스크린리더로도 핵심 행동을 할 수 있어야 한다.

## UI-01 홈 `/`
목표: 자격증 검색 또는 저장한 종목의 다음 행동으로 진입.
위→아래: 브랜드/탐색 → 검색 → 관심 종목 요약(client) → 확인된 접수 일정 → 유용한 가이드 → 출처/정책.
첫 방문에는 관심 빈 상태와 찾기 CTA를 제공한다. 가짜 인기순위를 만들지 않는다.
검색 submit은 `/qualifications?q=...`로. 일정 카드 선택은 종목 상세의 일정 섹션으로 이동한다.
상태: 저장소 실패(임시모드), 검증된 일정0(공식 조회 안내), 로딩, API stale.
완료: 390px 첫 화면에서 검색 입력과 주요 CTA를 찾을 수 있고 하단 nav가 콘텐츠를 가리지 않는다.

## UI-02 탐색 `/qualifications`
검색 + 등급/분야 filter + 결과 수(확인 가능시) + 목록 + 비교 tray.
공식 이름·검증 별칭만 매칭. 엔터 검색과 검색 버튼 모두 지원. q/filter는 URL로 복원된다.
카드에 종목명·등급·데이터 지원범위·상세·비교 선택을 둔다. 수수료/합격률이 없으면 숨기거나 미확인 표시.
비교 4번째 선택은 명확한 최대3개 안내. 전체 페이지를 리셋하지 않는다.
0건은 검색어 지우기/필터 초기화. 미지원 자격증을 가짜 상세로 만들지 않는다.

## UI-03 상세 `/qualifications/[slug]`
1. breadcrumb / 종목명·등급 / 관심 저장.
2. 다음 확인 일정(필기·실기 구분) / 공식 원문 이동 / stale notice.
3. 일정 전체 목록(접수·시험·발표·추가접수 구분) / ICS 선택.
4. 필기·실기 통계: 연도·회차 selector → 표본 수·비율 요약 → 차트 → 표.
5. 내 준비 계획 만들기 CTA.
6. 검증된 시험정보·수수료(optional) / 관련 가이드.
7. 출처·계산법·정정 안내.
모바일에서 첫 핵심 블록 위에 광고·대형 hero를 넣지 않는다.
정확한 시간 없는 접수일은 “시각 공식 확인”. 시험기간을 개인의 시험일처럼 D-day로 표시하지 않는다.
통계 제어는 키보드 사용 가능. 차트 실패 시 표는 유지한다.

## UI-04 일정 `/calendar`
현재 한국 월 기본. 이전/다음/오늘, 필기/실기, 등록/시험/발표 필터.
모바일 목록은 날짜 group, 데스크톱은 월 grid + 선택 날짜 목록을 제안한다.
기간 이벤트는 중간 날짜에도 포함되며 이름을 잘라 의미가 없어지지 않도록 한다.
종목 수를 “현재 지원 N종목”으로 표시하고 전국 모든 자격일정처럼 홍보하지 않는다.
긴 기간·동일 날짜 다수·오늘0건·빈 달·연말 이동을 테스트한다.

## UI-05 비교 `/compare`
최대3개 선택. 기본 필드는 종목/등급/다음일정/동일 연도·단계 통계/검증 수수료.
표 머리글은 필요한 범위 sticky. 모바일 가로 스크롤은 표 안에서만.
비교0개: 탐색 CTA. 1개: 추가 선택 안내. 2~3개: 비교 가능.
공통 연도가 없으면 기준을 명시하고 “순위” 표시를 하지 않는다.
공유는 canonicalized ids/year/stage만. 취소된 공유/clipboard 거부 시 URL 복사 fallback.
기간 중복은 가능성만 표시하며 개인 시간충돌은 확정하지 않는다.

## UI-06 내 준비 `/my-plan`
관심 목록 → 목표 계획 선택 → 일정/시간/학습항목 입력 → 계산 미리보기 → 저장 → 주차별 체크.
단계1 목표 종목·필기/실기·개인 목표일. 단계2 요일별 시간·제외일. 단계3 항목·비율·결과 검토.
저장 전에 총 가능시간과 배분 합계를 표시한다. 합격을 위해 필요한 시간이라는 표현 금지.
편집/삭제/체크/JSON 내보내기/ICS 내보내기. JSON 가져오기·서버 동기화는 P1.
브라우저 저장임을 초기 안내하고 저장 실패 시 영구 저장 성공 toast를 띄우지 않는다.
공식 일정 변경은 배너로 재검토를 제안하되 사용자 목표일을 자동 변경하지 않는다.
광고·개인 문구 분석·검색 색인은 제외.

## UI-07 가이드 `/guides`, `/guides/[slug]`
리스트에는 실제 검토 후 게시된 글만. 본문에는 제목·작성/검토일·대상·설명·근거·관련 기능.
자동 통계 요약과 편집 해설을 구분한다. 미확인 시험과목·응시자격·미래 일정을 AI로 채우지 않는다.
관리자 CMS 대신 Git Markdown draft/reviewed/published 메타데이터를 사용한다.

## UI-08 신뢰·정책
/about 서비스와 운영 주체, 공식기관 아님 안내.
/methodology 날짜·가중 합격률·불완전 연도·계획 계산.
/sources 실제 사용하는 데이터·조건·기준일.
/privacy 실제 저장/수집/광고/분석 구성에 맞는 운영자 검토 문안.
/terms 비공식 준비도구·정보 한계·공식 확인·권리·정정.
/contact 실제 수신 가능한 연락수단. 임의 운영자 개인정보로 채우지 않는다.
초안 정책이나 TODO 연락처는 운영에 게시하지 않는다.

## UI-09 운영자 `/admin`
로그인 → 수집 현황 → 미매핑/변경 검토 → old/new+근거 → 승인/보류/거절 → 감사 이력.
관리자 브라우저에서 raw secret/키/connection string을 노출하지 않는다.
종목별 공개 중단/재개, 재수집(대상 scope·쿼터), revision 충돌 경고 제공.
자신의 role을 바꾸는 UI는 만들지 않는다. 방문자에게 관리자 존재 여부 외 민감 정보는 노출하지 않는다.

## 공통 예외
404: 존재하지 않는 종목/가이드, 홈·탐색 복귀.
503: 마지막 정상 데이터도 없는 시스템 장애, 공식 출처와 재시도.
차단/권한오류: 로그인 필요/권한없음 구분. 계정 민감 정보 미표시.
전체 오류 boundary가 정상 데이터의 출처를 가짜 최신 시각으로 바꾸지 않는다.
