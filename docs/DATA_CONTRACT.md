# 데이터 계약·수집 설계 v2.0

> v2 구현 패키지: 기존 제품 범위를 유지한다. 상세 구현 규칙은 ARCHITECTURE.md, DATABASE.md, DOMAIN_RULES.md, ROADMAP.md를 함께 적용한다. 모든 구현·API 인증 호출·배포 상태는 현재 미실행이다.


기준일: 2026-10-20. 공개 카탈로그·명세 확인 단계이며 인증키 실호출은 미수행.
외부 API의 필드·등급 코드·승인 상태는 구현 시 재확인한다. 아래 내부 모델은 우리 서비스의 설계이며 외부 API 응답을 그대로 복사한 모델이 아니다.

카탈로그에는 이들 API가 무료로 안내되어 있다. 실제 사용 승인, 트래픽·쿼터의 단위와 주기, 운영계정 조건, 재배포·상업적 이용 범위는 계정과 데이터셋별로 확인·기록한다. DS-02·DS-03에는 운영단계 심의승인이 안내되어 있으므로 자동승인이라고 가정하지 않는다. 무료 API와 무료 웹 운영은 다르다.[S01~S05]

## 2. 공개 명세에서 확인한 연결 지점

DS-02 요청주소:
`https://apis.data.go.kr/B490007/qualExamSchd/getQualExamSchdList`

명세의 주요 요청 키: serviceKey, numOfRows, pageNo, dataFormat, implYy, qualgbCd, jmCd. 국가기술자격 코드 T와 종목 코드를 명시적으로 사용하되 실제 승인 키로 검증한다. 기본값에 맡겨 다른 자격 체계를 섞지 않는다.[S02]

DS-01 주요 응답 키: qualgbcd, seriescd, seriesnm, jmcd, jmfldnm, obligfldcd, obligfldnm, mdobligfldcd, mdobligfldnm. 코드 문자열의 앞자리 0을 보존한다.[S01]

DS-03 주요 요청 키: serviceKey, grdCd, baseYY, pageNo, numOfRows. 주요 응답 키: examPassCnt, examTypCcd, grdNm, implSeq, implYy, jmFldNm, passRate, recptNoCnt. 명세는 recptNoCnt를 응시자수로 설명한다.[S03]

종목 목록의 seriescd와 통계 요청의 grdCd를 같은 코드 체계로 가정하지 않는다. 별도 교차표가 필요하다. DS-03의 명세상 종목명만으로 내부 종목을 찾는 경우에는 검토된 매핑을 사용하며 모호한 매칭 결과를 자동 게시하지 않는다.

일부 공개 명세의 URL은 구형 HTTP 주소로 표시된다. 실제 연결에서 공식 HTTPS 주소·대체 게이트웨이·인증 전달 방식을 먼저 확인한다. 자동 HTTP 강등을 구현하지 않는다. 안전한 연동이 확인되지 않으면 해당 소스 연결을 보류하고 공식 링크 또는 검수된 합법적 자료 경로로 범위를 축소한다. API operation이나 HTTPS 지원을 추측해 성공 처리하지 않는다.

DS-05 카탈로그의 기본 선택 operation은 특정 등급의 일정일 수 있다. 이를 모든 종목의 수수료 API로 그대로 호출하지 않는다. 세부 기능 확인 전 수수료는 optional이다.

## 4. 정규화 모델

### 공통 출처·시간

모든 공개 레코드는 source_id, source_record_key(가능한 경우), source_url, source_published_at(nullable), fetched_at, validated_at, reviewed_at(nullable), data_as_of(nullable), verification을 추적한다.

fetched_at은 기술적 수집 시각이다. source_published_at은 공식 발표 시각이며 알 수 없으면 null이다. API 카탈로그 수정일은 개별 시험 공고 수정일이 아니다. 각 필드별 출처가 다르면 항목 단위로 표시한다.

### Qualification

내부 id, provider, qualification_type, acquisition_track, source_code(string), canonical_name, grade, domain, slug, active_state, publication_state.

기관과 자격체계를 포함한 식별 키를 사용한다. 공식 코드가 비슷하다는 이유로 다른 체계의 자격증을 통합하지 않는다. 폐지·명칭변경은 삭제 대신 이력과 적용 기간으로 관리한다.

### ExamEvent

qualification_id, year, round, stage, event_type, date_start, date_end, starts_at(nullable), ends_at(nullable), temporal_precision(date|datetime), extent(single|range), timezone, official_schedule_key, schedule_status, provenance.

stage는 written/practical 등 검증된 내부 코드이며 알 수 없는 값은 격리한다. event_type은 registration/exam/result/document_submission 등이다. 추가접수·빈자리접수·회차 하위 분류가 나타나면 원문 값을 보존하고 검증 전 기본 접수와 합치지 않는다.

date_start/date_end는 사용자 화면에서 포함 날짜다. `starts_at` 같은 정밀 시각은 실제 근거가 있을 때만 채운다. 기간형 시험에서 개인 시험시간·장소를 추정하지 않는다.

업서트 키는 안정적인 원천 ID를 우선 사용한다. 원천 ID가 없으면 종목·연도·회차·단계·이벤트 종류·하위 구분 등 안정적인 키를 만들고 충돌을 검증한다. 날짜를 키에 넣어 일정 정정이 새 일정으로 복제되게 만들지 않는다. 동일 키가 다수 후보와 충돌하면 자동 합치지 않고 검토로 보낸다.

### PassStatistic

qualification_id, source_grade, year, round, stage, acquisition_track, examinees(nullable integer), passed(nullable integer), published_rate(nullable decimal), calculated_rate(nullable decimal), scope_status, mapping_status, provenance.

수치 제약: examinees·passed ≥0, passed ≤examinees(분모 존재 시), 비율 0~100. null과 0을 구분한다. 원문 비율 문자열과 소수 정밀도를 보존한다. 응시자수와 접수자수를 혼용하지 않는다.

### Crosswalk·Review

source_id + 원천 종목명/코드 + 원천 등급 + 적용 연도 → 내부 qualification_id. 정확히 1개로 확인된 매핑만 publish 가능하다. 부분문자열·AI 추정·유사도 점수만으로 확정하지 않는다. 검토자·근거·변경 이력을 남긴다.

## 5. 통계 규칙

동일한 모집단 범위(종목·취득방식·단계)를 유지한다. 연도·회차를 섞기 전에 중복과 수집 완전성을 확인한다.

`annual_rate = SUM(passed) / SUM(examinees) * 100`

분모가 없거나 0이면 null이다. 공개 통계의 반올림 비율로 분모를 역산하지 않는다. 불완전 연도의 집계는 “수집된 회차 합산”으로 이름 붙이며 공식 연간 합격률로 표현하지 않는다. 전체 회차 확인 근거가 없으면 complete=true를 자동 설정하지 않는다.

공식 비율의 반올림 자릿수에 맞는 허용오차를 정의하고 테스트한다. 정당한 반올림 차이는 허용하되 실제 값의 불일치를 덮기 위해 큰 오차 한도를 두지 않는다. 차이가 설명되지 않으면 검토 대기로 둔다.

전년 대비 차이는 `%p`로 표시한다. 40%에서 45%는 +5%p이며 +5%라고 쓰지 않는다. 제도·명칭 변경으로 비교 연속성이 끊기면 그래프에 표시하고 변경 전후를 무조건 합치지 않는다.

## 6. 수집 주기·호출 예산 — 초기 설정 제안

| 작업 | 기본 주기 | 보완 |
|---|---|---|
| 종목 목록·상세·수수료 | 주 1회 | 공식 변경 확인 시 제한된 수동 재수집 |
| 현재·차년도 일정 | 일 1회 | 접수 임박 지원 종목만 승인 쿼터 안에서 6시간 간격 |
| 과거 완료연도 통계 | 주 1회 | 변경·정정 탐지, 최초 backfill은 분산 수행 |
| 당해연도 통계 | 주 1회 | 발표 시기만 허용 범위에서 일 1회 검토 |

이는 공급기관 갱신 주기 보장이 아니라 우리 서비스의 초기 수집 설정이다. 운영 한도에 맞춰 조정한다.

`예상 호출량 = 조회 구간 수 × 페이지 수 × 실행 횟수 + 제한된 재시도`

연도·등급 단위 조회를 지원하는 API는 결과를 한 번 가져와 재사용한다. 종목별로 동일한 전체 통계를 중복 요청하지 않는다. 일별 예산·서비스별 예산·동시성·재시도 상한을 설정한다. 상태코드 429 또는 쿼터 오류에 무한 재시도를 하지 않는다.

## 7. 수집 파이프라인

허용된 요청 구성 → 비밀키를 제외한 요청 식별 해시 → 응답 원문 임시 보관 → HTTP와 업무 결과코드 확인 → 안전한 XML/JSON 파싱 → 전체 페이지 수집 → 스키마 검증 → 코드 매핑 → 중복·비율·범위 확인 → staging → 변경 검토 → 원자적 공개 스냅샷 교체 → 캐시 갱신 → 실행 결과 기록.

XML 외부 엔티티·DOCTYPE 처리로 외부 요청이 발생하지 않게 하고 응답 크기·깊이·시간 한도를 둔다. ServiceKey/serviceKey의 대소문자와 인코딩 요구는 어댑터별로 검증한다. 이미 인코딩된 키를 재인코딩하지 않도록 실제 호출 테스트를 둔다.

부분 페이지 실패 시 이를 전체 조회 성공으로 취급하지 않는다. 마지막 정상 공개본을 보존한다. 0건 응답만으로 기존 전체 데이터 삭제를 실행하지 않는다. 중복 실행 방지·실패 지점 재개·run_id·호출 비용·처리 건수·격리 건수를 기록한다.

## 8. 최신성·장애·정정

일정 공개본의 마지막 성공 검증이 48시간을 넘으면 기본적으로 stale로 표시한다. 접수 임박 시 더 엄격한 임계치를 적용할 수 있다. 이 값은 서비스 운영 목표이며 공식 데이터의 정확성 보증은 아니다.

last_success_at이 최근이어도 내용의 공식 기준일이 오래될 수 있다. 두 정보를 함께 표시한다. 변경 감지 시 old/new·출처·확인 시각을 검토 대기열에 기록한다. 날짜·종목 매핑의 중대한 변화는 검토 전 공개하지 않는다.

복구 후에도 격리 중인 새 데이터가 기존 정상본을 덮지 않게 한다. 사이트 자체 오류와 공식 미발표·미지원 상태를 구별한다. 관리자 강제 수정은 원문에 직접 덮어쓰지 않고 근거 있는 override 기록으로 관리한다.

## 9. 보안·보존

공공 API 키와 수집용 Supabase 비밀키는 서버 환경변수에만 둔다. 요청 URL의 키, Authorization 헤더, DB 연결 문자열이 로그·오류·스크린샷·저장소에 남지 않게 마스킹한다. 실제 이용자 비밀정보는 애초에 수집하지 않는다.

공개된 읽기 데이터, 원문·수집로그, 관리자 권한을 분리한다. RLS는 공개 스키마 전체에 적용하고 필요한 읽기 권한만 명시적으로 부여한다. privileged view/function이 권한 우회를 만들지 않는지 검사한다.[S12][S13]

원문 보존 초기안은 30일, 최근 오류 원문과 공개본 변경 근거는 별도 관리한다. 실제 보존 기간은 데이터 조건·운영 필요·비용 검토로 확정한다. 이 기간을 법정 기준으로 설명하지 않는다. 백업은 접근 제한된 곳에 저장하고 복원 테스트를 수행한다.
