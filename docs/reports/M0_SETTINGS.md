## 키를 설정할 때

1. DS-01(15003024), DS-02(15074408), DS-03(15089380)의 실제 활용 승인 상태를 각각 확인한다. 개발 승인과 운영 승인을 나눈다. 무료 안내·승인 정책 설명은 현재 계정 승인 증거가 아니다.
2. [.env.example](../../.env.example)은 값 없는 설정 양식이다. 무시되는 로컬 `.env.local` 또는 승인된 서버 secret 관리 화면에서 `DATA_GO_KR_SERVICE_KEY`를 직접 설정한다. 키를 채팅·CLI 인수·공유 문서로 전달하지 않는다. 현재 앱이나 dotenv loader는 없으므로 파일 작성만으로 연결이 되지 않는다. 후속 probe가 안전하게 읽는 방식을 구현해야 한다.
3. API별 키가 다른 경우 후속 어댑터 계약에서 별도 서버 변수명을 확정한다. 임의의 키를 다른 데이터셋·프로젝트에서 재사용하지 않는다. `NEXT_PUBLIC_` 접두사에 secret을 넣지 않는다.
4. 키 존재, HTTPS 요청 성공, HTTP 상태, 업무 결과코드, 항목·페이지 수, 공식 대조 결과를 따로 기록한다. 키가 포함된 URL·헤더·에러 원문은 기록하지 않는다. ServiceKey/serviceKey와 인코딩 방식은 공개 명세 및 실제 응답으로 검증한다.
5. 조회 예산·페이지 크기·호출 횟수·재시도 상한은 실제 승인 쿼터를 확인한 뒤 정한다. 이번에는 인증 호출을 하지 않았다.

현재 환경에 키가 없다는 관측은 사용자 계정에 키나 승인이 없다는 뜻이 아니다. GitHub 연결은 확인됐으나 공공데이터포털 로그인 세션은 확인하지 않았다. DB·호스팅 연결 도구 노출도 실제 프로젝트 선택·접속·승인을 보장하지 않는다.
