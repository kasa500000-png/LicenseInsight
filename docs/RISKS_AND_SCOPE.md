## 범위 변경 규칙
새 기능은 문제/사용자/효과/데이터/비용/보안/테스트/기존 STEP 영향으로 검토한다.
원래 P0가 끝나기 전에 방문자 로그인·AI 상담·알림·다른 시행기관·문제은행을 끼워 넣지 않는다.
필수 수정은 해당 STEP에 포함하고 미관 polish나 확장은 별도 backlog로 남긴다.
사용자 요구가 변경되면 docs/PRD.md의 FR와 ROADMAP/acceptance를 함께 갱신한다.
테스트 실패를 없애기 위해 제품 요구를 낮추지 않는다.

## v2 결정
D01 기존 제품 범위 유지, 이전20 TASK를 STEP-01~20으로 재배열.
D02 날짜 precision과 range 분리; 모르는 시간 채우지 않음.
D03 광고OFF/분석 구조를 QA·공개 이전에 배치.
D04 개인기록은 브라우저; JSON import·계정 sync는 P1.
D05 데이터 검증과 코드 테스트의 상태를 별도 표시.
D06 루트 AGENTS는 짧게, 상세 문서는 해당 STEP만 읽어 컨텍스트 낭비 방지.
D07 원격 자원에 대한 권한과 실행 근거는 state/APPROVALS에서 별도 기록.
