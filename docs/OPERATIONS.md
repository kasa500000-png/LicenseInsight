# 운영·예약 수집·비용·복구

이는 구현 요구사항이며 현재 예약 작업이나 모니터가 생성된 것은 아니다.

## 수집 설정 제안
목록/상세/수수료 주1회, 현재/차년도 일정 일1회, 접수 임박 종목6시간 간격(승인 quota 내),
완료연도 통계 주1회, 당해연도는 기본 주1회와 발표 시기 제한 조정.
공급기관 갱신 보장이 아니라 운영 설정이다. 시점별 실제 제공 범위·요청단위에 맞게 조정한다.
예상 호출량 = source별 scope 수 × page 수 × 실행횟수 + 상한 있는 재시도.
등급/연도 일괄 통계를 종목마다 중복 호출하지 않는다.

## 실행기
상업 호스팅에서 지원하는 예약 기능 하나를 선택한다. Vercel을 택하면 플랫폼 Cron 요구사항을 따른다.[S18]
서버리스 프로세스 안에 상주 setInterval/node-cron을 두고 지속 실행을 기대하지 않는다.
시간대/실행정밀도/함수 제한/재시도 정책은 실제 플랜과 문서에서 확인한다.
기관 요청은 HTTPS allowlist, service-key 비출력, concurrency/timeout/payload/page limit.
request signing/CRON_SECRET 등 기계 인증과 scope lease로 중복 실행을 방지한다.
소스 제공 중단·429·업무 쿼터 오류는 backoff/circuit breaker로 중단한다. 무한 retry 금지.

## 데이터 최신성
일정 자동 검증이 48시간 초과면 기본 stale 제안. 접수 임박이면 더 엄격하게 설정 가능.
통계는 자료연도/발행시각과 기술 수집시각을 별도로 보여준다.
변경 대기 중 기존 값은 “변경 확인 중”으로 표시하고 최근 fetch로 freshness를 위장하지 않는다.
원문 changed hash가 자동 검증을 통과해도 중대한 날짜/종목매핑 변경은 review를 거친다.

## 관측
source별 성공률, last_validated_at, 호출 예산, 처리/격리/누락 건수,
public read latency, 5xx, 관리자 검토 대기, 광고/분석 실패, 비용 추세.
로그에는 안전한 error code/run ID만. secret URL·쿠키·계획 텍스트를 저장하지 않는다.
무료 플랜의 로그 보존·알림 기능은 지원 여부를 확인한다. 실제로 없는 모니터를 active라고 보고하지 않는다.

## 비용
| 항목 | 확인 방식 |
|---|---|
| 도메인 | 구매/갱신/세금 실제 견적 |
| 호스팅 | 상업적 이용 가능한 플랜 + 사용량 초과·빌드·전송 |
| DB | 프로젝트·저장·egress·백업·auth 사용량 |
| 예약 수집 | 실행횟수·duration·API quota |
| 모니터/분석/CMP | 필요한 기능·요금·추가 이벤트 |
| 개발 도구 | GPT/Codex 구독/과금과 서비스 운영비 분리 |
| 서비스 LLM | MVP 0호출 |

운영 월 예산은 사용자 확정 전 UNSET. 임의 결제를 하지 않는다.
예산 50/80/100% 안내와 수집/광고 OFF 같은 동작은 정책 제안이며 실제 공급자 지원을 확인한다.
지출 알림이 청구를 완전히 막는다고 보장하지 않는다. 과금 상한/중단 조건을 별도로 확인한다.

## 백업/보존
초기 원문30일은 제안이며 법정 기준이 아니다. 공개 변경 근거/감사 이력은 필요에 따라 별도 보존.
정규화 데이터 + mapping + publication revision + migration + 콘텐츠를 백업 대상으로 한다.
키 본문은 백업 ZIP/공개 Git에 넣지 않는다. secret 복구는 승인된 관리자 경로로 별도.
개인 브라우저 계획은 서버 백업 대상이 아니며 JSON export로 사용자가 보관한다.
복원 실습은 별도 DB에 수행하고 record count/hash/RLS/public read를 확인한다.
RPO/RTO 목표는 운영자가 정하고 실제 복원 결과와 구분한다. 초기 제안은 RPO24h/RTO4h, SLA 보장 아님.

## 장애 대응
1. 영향 파악: 일정/통계/저장/광고 중 어느 부분인지 구분.
2. 잘못된 신규 게시·반복 수집을 중단하고 정상 공개본 유지.
3. 사용자에게 정확한 기준시각·오류/변경 확인 상태 표시.
4. 원문/변경/권한/로그 근거로 최소 수정.
5. 회귀 테스트와 데이터 대조 후 복구; 원인/재발 방지 기록.
광고 장애는 광고만 OFF. 코드 rollback과 DB rollback은 다르며 migration 호환을 먼저 확인한다.

## 공개 배포
대상 team/project/repo/commit/DB/environment를 실제 값으로 확인한다.
STEP-19에서 승인된 preview부터 검증한다. 공개는 출시 게이트와 실제 승인 후만.
Git push가 자동 배포를 유발할 수 있으므로 연동 여부와 production branch를 확인한다.
테스트된 commit/환경이 최종 배포와 일치하는지 확인한다. preview build 성공은 운영 배포 성공이 아니다.
운영 배포는 실제 도메인·HTML·데이터·광고OFF·관리자 보호 smoke test까지 기록한다.
