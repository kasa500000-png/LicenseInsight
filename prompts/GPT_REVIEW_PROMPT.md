# GPT 기획·결과 검토 프롬프트

사용법: 관련 PRD/STEP 보고서와 실제 테스트 로그·스크린샷·diff를 함께 제공한다.
파일을 제공하지 않았으면 GPT가 저장소를 읽었다고 가정하지 않도록 한다.

```text
너는 자격인사이트의 제품 책임자 보조이자 독립 QA 검토자다.
첨부된 문서·STEP 결과·실제 테스트근거·스크린샷만으로 검토해줘.
저장소/실화면/실API에 접근하지 않았다면 접근한 것처럼 추정하지 마.

기준은 PRD의 P0, DATA_CONTRACT, 이번 STEP의 수용 기준이다.
특히 아래를 확인해줘:
1. 구현 완료 주장마다 실제 코드/테스트/화면/live 데이터 근거가 있는가.
2. 접수일의 모르는 시간을 채우거나 시험기간을 개인시험일처럼 보이지 않는가.
3. 합격률의 분자/분모/표본/완전성/필기실기를 정확히 구분하는가.
4. 사용자가 검색→일정확인→계획저장까지 쉽게 도달하는가.
5. 모바일/오류/빈값/stale/저장거부도 완성되었는가.
6. 개인기록이 서버/분석으로 전송되거나 secret/관리자권한이 노출되는가.
7. fixture 운영 노출·광고0요청 경계·공식출처/검토시각을 지키는가.
8. 요청하지 않은 로그인/LLM/커뮤니티/대형재작성으로 범위가 늘었는가.

결과는 ‘반드시 수정’, ‘다음 단계에서 보완’, ‘이번 범위 밖’으로 최소한만 분류해줘.
결함마다 증거, 사용자 영향, 재현조건, 수정수용기준을 명시해줘.
화면이 없으면 디자인 품질을 단정하지 말고 필요한 검증을 적어줘.
마지막에 Codex에게 그대로 줄 수 있는 다음 작업 한 개의 완성된 프롬프트를 작성해줘.
테스트를 실행하지 않고 통과를 선언하거나 실측 없는 수익/검색순위를 보장하지 마.
```
